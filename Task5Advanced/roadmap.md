# Стратегический роадмап внедрения Data Mesh

## Этап 1. Пилот (0–6 месяцев)

Что делаем: 
- фундамент платформы (Kafka + Schema Registry + DLQ — единые принципы работы с событиями из кейса; Lakehouse; IaC-модули сред; CI/CD ); 
- пилотных продукт «Финансовые расчёты» и 
-  пилотных продукт «Пациентский поток»
- первая NRT-витрина и прототип конструктора отчётов; базовый governance.


Привязка к бизнес-целям: архитектурное решение согласовано, границы доменов определены, проекты витрины запланированы. 

Критерий: пилотная витрина строит отчёт за минуты, границы доменов подтверждены.

## Этап 2. Масштабирование (6–18 месяцев)

Что делаем: 
- подключение критических доменов (кредитование, антифрод, ИИ-метрики, персонал/инвентаризация); 
- потоковые витрины в проде; 
- портал самообслуживания для всех доменов с RBAC; 
- мосты для легаси (CDC из DWH и антикоррупционные слои для Camel ); 
- каталог DataHub с метриками качества и ownership; 
- FinOps-бюджеты доменов.


Привязка к бизнес-целям: портал самообслуживания реализован, бизнес-пользователи работают в новой архитектуре, легаси временно сохраняется в отдельных доменах.

## Этап 3. Поддержка и развитие доменов (18–36 месяцев)

Что делаем: 
- домены выпускают дата-продукты самостоятельно
- geo-развёртывание под 2–3 новых региона с учётом локализации данных
- вывод DWH, Camel и PowerBuilder из эксплуатации

Привязка к бизнес-целям:  масштабирование по продуктам; целевая архитектура - слабосвязанная событийная платформа
