# Агрегаты доменов

## Контекст «Пациентский поток»

### Пациент

Границы: демографические данные, контакты, согласия на обработку; ссылка на профиль клиента группы.

Ключ: `patient_id` (UUID). 

Инварианты: пациент не может быть зарегистрирован без подписанного согласия на обработку ПДн; один пациент — один активный `customer_id`.

События: `patient.registered`, `patient.consent.revoked`.

### Запись на приём

Границы: слот, врач, пациент, услуга, статус.

Ключ: `appointment_id`. 

Инварианты: один слот врача не может быть занят дважды; запись нельзя подтвердить в прошлое; отмена возможна только до начала приёма.

События: `appointment.scheduled`, `appointment.cancelled`.

### Приём

Границы: факт визита, оказанные услуги, направления, ссылка на заключение ИИ. 

Ключ: `encounter_id`. 

Инварианты: приём завершается только с заполненным перечнем услуг; ссылки на исследования валидны в контуре меддата.

События: `encounter.started`, `encounter.completed`.

## Контекст «Медицинские данные» (защищённый контур)

### Медицинская карта

Границы: история болезни, диагнозы, назначения. 

Ключ: `record_id` + `patient_id`. 

Инварианты: запись изменяется только аутентифицированным медработником; удаление запрещено.

События: `study.ordered`, `study.completed` 

### Исследование

Границы: тип, статус, результат, ссылка на заключение ИИ.

Ключ: `study_id`. 

Инварианты: результат прикрепляется только к назначенному исследованию; 

## Контекст «ИИ-диагностика»

### Заключение ИИ

Границы: ссылка на исследование, версия модели, результат/уверенность, статус проверки врачом.

Ключ: `assessment_id`. 

Инварианты: заключение всегда привязано к конкретной `model_version` (воспроизводимость); заключение без подтверждения врача не считается диагнозом.

События: `ai.assessment.completed`

## Контекст «Счета и платежи»

### Счёт 

Границы: позиции, сумма, плательщик, статус.

Ключ: `invoice_id`

Инварианты: сумма = сумме позиций; счёт по одному приёму выставляется ровно один раз; аннулирование — только неоплаченного счёта.

События: `invoice.issued`, `invoice.paid`, `invoice.cancelled`.

### Платёж

Границы: сумма, источник (карта/кредитные средства), связка со счётом.

Ключ: `payment_id`. 

Инварианты: платёж не может превышать остаток по счёту; повторная обработка того же `external_tx_id` не создаёт второй платёж.

События: `payment.received`, `payment.failed`.

## Контекст «Кредитование»

### Кредитная заявка

Границы: заявитель, сумма, цель, статус, результат скоринга.

Ключ: `application_id`. 

Инварианты: решение принимается только при наличии оценки риска; одна активная заявка на клиента и цель.

События: `loan.application.submitted`, `loan.application.approved`, `loan.application.rejected`.

### Кредитный договор

Границы: условия, график платежей, статус обслуживания.

Ключ: `agreement_id`. 

Инварианты: договор создаётся только из одобренной заявки; сумма договора = одобренной сумме; график платежей покрывает тело + проценты полностью.

События: `loan.agreement.created`, `loan.payment.overdue`, `loan.agreement.closed`.

## Контекст «Антифрод»

### Оценка риска

Границы: субъект оценки (заявка/транзакция), скоринговый балл, факторы, версия правил.

Ключ: `score_id`. 

Инварианты: оценка неизменяема после вынесения; 

События: `fraud.risk.scored`.

## Контекст «Клиентский профиль» 

### Клиент группы

Границы: сквозной профиль, связи с доменными идентификаторами, согласия по направлениям.

Ключ: `customer_id`. 

Инварианты: слияние профилей не теряет доменные ссылки; согласия на кросс-доменное использование данных проверяются при каждом обращении из другого домена.

События: `customer.created`, `customer.merged`.

## Контекст «Персонал и инвентаризация»

### Сотрудник 

Границы: штатная позиция, квалификация, допуски. 

Ключ: `employee_id`. 

Инварианты: врач без активного допуска не может быть назначен в слот записи.

События: `hr.employee.hired`, `hr.employee.terminated`.
